ABOUT TASK 1(GRAPHING THE DEPTH):
The objective of the code is to process the depth-sensor data and produce a clear depth-versus-time graph while accounting for the noise and corrupted readings that can occur in real-world sensors. I first used `pandas` and `read_csv()` to import the provided CSV file.Then, I used `to_numeric()` with `errors="coerce"` to make sure that the depth values are treated as numerical data while converting the corrupted entries(like #VALUE!) into missing values. I then used statistical measures such as the first and third quartiles (`quantile()`) and the interquartile range (IQR) to identify readings that fall outside the expected range(like the reading of -1271.1m), and replaced these unrealistic  values with more probable values using `interpolate()`.I used `bfill()` and `ffill()` to handle any remaining missing values at the ends of the dataset.After removing the extreme spike,I applied a rolling median with a window of five readings to reduce the effect of smaller sudden fluctuations. This was followed by a rolling mean, which further smoothed the curve and made the overall change in depth easier to observe. 

Because of this, the graph actually represented the actual trend of the ship's depth while preventing a single corrupted sensor reading from producing a misleading sudden drop. `matplotlib.pyplot` was used for visualization, with `plot()` displaying the data and `xlabel()`, `ylabel()`, `title()`, `legend()`, and `grid()` making the graph clear and readable. Finally, `FuncAnimation` was used to simulate real-time monitoring by adding one new data point every second, as required by the task. Each keyword and function was chosen based on the specific role it plays in converting raw sensor readings into a cleaner, more interpretable, and continuously updating depth graph.

Circuit Design:

The circuit uses all six components mentioned in the induction document to represent one piece of the ship's monitoring needs: a photoresistor (light sensor) to detect storms, an ultrasonic distance sensor to detect proximity to Charybdis, a pushbutton for manual anchor control, an LCD to continuously display the current state, an LED for a visual storm warning, and a piezo buzzer for an audible Charybdis warning. The photoresistor is wired as a voltage divider (paired with a fixed 10kΩ resistor between it and ground) because a photoresistor only changes resistance with light — it needs a partner resistor to convert that resistance change into a readable voltage at the analog pin. The pushbutton uses the Arduino's internal pull-up resistor (INPUT_PULLUP) rather than an external resistor, which simplifies the wiring to just two connections (signal pin and ground) while still guaranteeing a stable, noise-free reading when the button isn't pressed. The LCD is wired in 4-bit mode (using only DB4–DB7 instead of all eight data lines) since this is the standard, pin-efficient configuration supported by the Arduino's LiquidCrystal library, and it uses two shared ground connections (for logic ground and backlight ground) since all ground pins on the Arduino are electrically equivalent.

Code Design:

The program is structured as a finite state machine, using a C++ enum to represent the five possible ship conditions (OPEN_SEA, ANCHOR_DROPPED, STORM, CHARYBDIS, WRECKED) as a single variable that can only ever hold one value at a time — this avoids the ambiguity and bugs that come from tracking multiple independent boolean flags. Each state transition is written as a self-contained condition check (e.g., "if currently OPEN_SEA and the storm condition is true, switch to STORM"), which keeps the logic easily traceable back to the specification's state diagram. Outlier-prone sensor timing (the ultrasonic pulse/echo cycle) is isolated into its own readDistanceCM() function to keep loop() readable. The 5-second wreck timer uses millis() (elapsed time since power-on) rather than delay(), because delay() would freeze the entire program — including sensor reads and the anchor button — for the duration of the wait, whereas millis() allows the program to keep checking all conditions every loop cycle while still accurately tracking elapsed danger time. The anchor button uses edge detection (comparing the current reading to the previous loop's reading) rather than a direct level check, since without it a single physical press would be registered thousands of times within the button's press duration, causing rapid, unintended toggling.
